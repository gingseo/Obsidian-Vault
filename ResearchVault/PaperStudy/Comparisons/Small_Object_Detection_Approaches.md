# 비교 축
작은 객체 탐지 성능을 어디에 개입해서 끌어올리는지 — feature 표현 강화, label assignment/sampling, 연산 가속(sparse computation), 아키텍처 경량화, end-to-end 구조 개선 중 어느 축에 해당하는지로 분류한다.

# 분석
- **DETR·Deformable Convolutional Networks·Deformable DETR은 비교표에서 제외**: [[DETR]], [[Deformable_Convolutional_Networks]], [[Deformable-DETR]]는 이 비교축(기존 detector에 어떻게 개입하는지)의 대상이 아니라, 이후 여러 논문이 기반하는 계보의 출발점(순수 foundational 아키텍처/모듈)이라 위 표에는 넣지 않았다. 나머지 논문들이 "무엇에 개입하는가"를 다루는 반면, 이 셋은 애초에 "개입할 기존 구조 자체(anchor·NMS 파이프라인, CNN의 고정 grid 샘플링, DETR의 전역 attention)"를 재정의한 논문이라는 점에서 층위가 다르다. Deformable DETR은 DETR의 느린 수렴·소형 객체 열세 문제를 deformable attention(Deformable Convolutional Networks의 offset 아이디어를 attention으로 이식)으로 해결한 논문으로, 뒤이어 처리하는 DQ-DETR 등 dynamic query DETR 계열 6편의 공통 baseline이다.
- **공통 경향**: 13편 중 10편이 "기존 detector에 plug-in 모듈을 추가"하는 방식(FANet, feature-info-driven-gaussian, sr-tod, rs-tod, detection-oriented-rectification, unc-sod, ffsstd-net, cdatod-diff, orfenet, ffca-yolo)이며, 새 아키텍처를 처음부터 설계한 논문은 없다 — 이 분야는 지금 대부분 "기존 백본/헤드를 어떻게 보강할 것인가"에 집중되어 있다.
- **Feature 강화 계열 내부의 차이**: FANet(주파수), feature-info-driven-gaussian(정보량+위치), sr-tod(reconstruction 부산물), rs-tod(공간 attention), ffsstd-net(SR 기반 auxiliary branch), orfenet(이진 마스크 재구성 + 다중 receptive field), ffca-yolo(atrous 지역 문맥 + 채널별 학습 가중 융합 + GCNet 계열 전역 attention), bafnet(전경+배경 이중 attention + boundary auxiliary supervision), rtp-net(수용영역-texture 협업 최적화), colr-det(latent SR 정규화 + saliency 기반 non-destructive routing)는 모두 "약한 feature를 어떻게 보강할지"를 다루지만 신호를 얻는 소스가 다르다 — 이 아홉 편을 하나로 묶어 "어떤 신호가 실제로 tiny object의 위치/존재를 가장 잘 드러내는가"라는 질문으로 다시 비교해볼 가치가 있다. 특히 orfenet은 ablation에서 "다중 소스를 쓴다"는 것 자체의 기여가 "동적으로 가중한다"는 정교화보다 훨씬 크다는 점을 수치로 보여줘(Table III, +0.9 vs +0.2), 이 계열 전체에 반복되는 패턴을 뒷받침한다. bafnet은 이 패턴에서 예외적인데, DSAM(+2.3)과 Boundary-Aware Branch(+2.7)의 개별 기여가 비슷한 수준으로 나뉜다 — 두 모듈이 서로 이질적인 정보(전경/배경 문맥 vs 경계 디테일)를 다루기 때문일 가능성이 있다. colr-det도 유사한 패턴을 보이는데, saliency 라우팅 단독으로는 AP_s가 오히려 하락하고(0.487→0.474) SR 브랜치와 결합해야만 크게 개선(0.649)되어(Table VI), "이질적 신호 간 시너지"가 "단일 신호의 정교화"보다 중요하다는 점이 이 계열에서 반복 확인된다.
- **연산 가속(sparse computation) 축이 새로 생김**: querydet과 ffsstd-net(CFD 모듈)은 "무엇을 계산할지"를 좁혀 연산량 자체를 줄인다는 공통점이 있다 — querydet은 FPN 레벨 간 sparse convolution, ffsstd-net은 patch 단위 필터링으로 구현 층위는 다르지만 동일한 coarse-to-fine 사상을 공유한다. 나머지 논문들이 대부분 "정확도"만 보고하는 데 비해 이 두 편은 FPS/연산 비용을 정면으로 다룬다는 점에서 lsod-yolo(경량화 축)와 목적의식이 겹친다.
- **label assignment 축에 cdatod-diff 추가**: unc-sod에 이어 cdatod-diff도 "어떤 prior를 positive로 볼지"를 동적으로 바꾸는 계열에 속한다. 다만 unc-sod는 예측 박스의 uncertainty를, cdatod-diff는 CLIP의 의미 정보를 기준으로 삼는다는 점에서 신호의 출처가 다르다 — 두 방법을 결합하면 "기하학적으로도, 의미적으로도 타당한" 샘플링이 가능할 수 있다.
- **원격탐사(항공뷰)·SAR 특화 vs 범용**: FANet, rs-tod, uav-detr, ffsstd-net은 원격탐사/드론뷰 이미지에, cdatod-diff는 SAR 영상에 특화되어 있고, 나머지(unc-sod, detection-oriented-rectification, feature-info-driven-gaussian, sr-tod, lsod-yolo, querydet)는 SODA-D 같은 지상 시나리오까지 포괄하는 범용 벤치마크를 함께 본다. 항공뷰 특화 논문들은 공통적으로 "주파수 도메인" 정보를 쓰는 경향이 있다(FANet, uav-detr) — 항공 이미지의 반복적/주기적 텍스처 특성과 관련 있을 가능성. SAR는 이번에 cdatod-diff로 처음 다뤄진 센서 도메인.
- **경량화·연산 효율 축 확장**: lsod-yolo(파라미터 경량화)에 이어 querydet·ffsstd-net(연산 가속), ffca-yolo(PConv 기반 backbone 재구성), rtp-net(depthwise separable 병렬 커널)까지 더해지며 "정확도"만이 아니라 "효율"을 정면으로 다루는 논문이 다섯 편으로 늘었다 — 실제 배포(엣지/실시간) 관점에서 이 다섯 편을 하나의 갈래로 놓고 비교할 가치가 있다. 특히 lsod-yolo와 ffca-yolo는 둘 다 "성능 유지하며 경량화"를 목표로 하지만 전략이 상반된다 — lsod-yolo는 저기여 검출 헤드(P5) 자체를 제거하는 구조적 재배치인 반면, ffca-yolo(L-FFCA-YOLO)는 backbone 컨볼루션 연산을 PConv로 대체하는 연산 층위의 경량화다. rtp-net은 이 중 유일하게 "정확도 개선"과 "GFLOPs/파라미터/FPS 동시 개선"을 모두 정량적으로 입증한 사례로, 별도의 경량판(L-FFCA-YOLO, LSOD-YOLO처럼)을 만들지 않고도 기본 설계 자체로 이를 달성했다는 점이 특이하다.
- **DETR → RT-DETR → UAV-DETR 계보**: DETR이 2020년에 처음 지적한 "소형 객체(APS) 성능 열세"라는 한계는 이 위키의 거의 모든 feature 강화 논문이 (다른 아키텍처에서) 다루는 문제와 동일한 문제의식이다. UAV-DETR은 RT-DETR(DETR의 실시간화 후속작)을 기반으로 주파수 도메인 모듈을 추가해 이 한계에 대응하지만, 원조 DETR 자체에 이 위키의 feature 강화 기법(reconstruction, 정보이론 기반 등)을 직접 적용한 사례는 아직 없다.

## Dynamic Query DETR 계열 (DQ-DETR, Density-Aware DETR, IG-DETR, PaQ-DETR, DQA-DETR, DQP-DETR)

Deformable DETR의 극도로 느린 수렴과 소형 객체 열세를 해결하는 과정에서 파생된 6편은 모두 "DETR의 object query를 이미지 내용에 따라 동적으로 조정한다"는 상위 아이디어를 공유하지만, 실제로 **어떤 신호를 쓰고 그 신호를 어디에 적용하는지**가 뚜렷이 갈린다. 이를 기준으로 두 하위 갈래로 나뉜다.

**하위 갈래 A — 전역 밀도(density map) 기반, [[Density_Guided_Dynamic_Query]] 개념** (DQ-DETR, Density-Aware DETR, IG-DETR, DQP-DETR 4편)
이미지 전체의 인스턴스 분포를 요약한 density map으로 "몇 개의 query를 어디에 배정할지"를 정한다. 4편 사이에서도 밀도 신호를 다루는 방식이 점차 확장되어 왔다:
- **query 개수 산정 방식**: DQ-DETR은 4단계 이산 분류(회귀 시 AP 25.9→14.9로 급락하는 것을 직접 확인해 분류를 채택), IG-DETR은 이를 6단계로 세분화, Density-Aware DETR은 반대로 crowd counting 기법을 응용한 연속 회귀(Density Focal Loss)로 전환해 DQ-DETR과 동일 baseline(DINO) 위에서 직접 대조 실험을 수행하고 회귀의 우위(30.2→32.1 AP)를 실증했다. DQP-DETR은 다시 회귀 기반 density map을 쓰되 query 개수뿐 아니라 그 자체를 encoder memory와 토큰 순위에까지 확장한다.
- **density 신호의 적용 범위**: DQ-DETR·IG-DETR은 density map을 query 개수 산정과 encoder feature 강화(전자는 곱셈 마스킹, 후자는 덧셈 residual `1+W`) 두 곳에 쓴다. DQP-DETR은 여기에 (1) encoder memory로의 양방향 cross-modulation 주입(BCME), (2) 토큰별 우선순위를 GT 밀도 기반 참조와 비교해 직접 감독하는 margin ranking loss(RCS)까지 더해 이 계열에서 가장 포괄적으로 밀도 정보를 활용한다.
- **공통 관찰**: 4편 모두의 ablation에서 "다중 신호를 쓴다는 것 자체"(feature 강화·density 주입)의 기여가 "그 신호를 얼마나 정교하게 다루는가"(세분화, 회귀 vs 분류 등)의 기여보다 일관되게 크다 — 예컨대 DQP-DETR은 ADPG+BCME만으로 AP +0.6인데 RCS(토큰 순위 학습) 추가로 +2.1이 더 붙고, Density-Aware DETR은 IDE&QA(밀도 기반 개수 조정)만으로 전체 개선폭의 대부분(+4.6/+6.1)을 차지한다.

**하위 갈래 B — 인스턴스 레벨(개별 후보 간 관계·품질) 기반, [[Pattern_Quality_Aware_Query_Refinement]] 개념** (PaQ-DETR, DQA-DETR 2편)
전역 밀도가 아니라 개별 query 후보 간의 공간적 유사도(패턴)와 개별 품질을 직접 신호로 쓴다.
- PaQ-DETR: dense candidate를 만든 뒤 Pattern-Aware Clustering(유사 후보 **병합**)과 Quality-Aware Pruning(저품질 **제거**) 2단계로 정제. 유일하게 COCO 일반 객체 탐지에서 검증(다른 5편은 항공/원격탐사 특화 벤치마크 중심)했다는 점도 독보적.
- DQA-DETR: 유일한 oriented(회전) object detection 사례. One-to-one matching에서 유사 고품질 query가 서로 negative로 경쟁하며 gradient를 왜곡한다는 것을 focal loss 수식으로 직접 증명하고(6편 중 유일한 이론적 분석), 이를 "제거"가 아니라 attention 기반 **병합**(Query Aggregator)만으로 해결한다는 점에서 PaQ-DETR과 다르다 — 병합 대상 선정에 쓰는 4단계 밀도 분류(ACP)는 하위 갈래 A의 요소도 일부 포함하는 경계 사례.

**갈래 간 비교**: 하위 갈래 A는 "얼마나 많은 query가 필요한가"라는 양(quantity)의 문제에 집중하는 반면, 하위 갈래 B는 "이미 있는 query 중 무엇이 중복이고 무엇이 저품질인가"라는 구성(composition)의 문제에 집중한다. DQA-DETR과 [[QueryDet]]의 Table 8(query 900→2400 확장 시 baseline 성능 붕괴, 55.29까지 하락)은 이 위키 전체를 통틀어 "query를 단순히 늘리는 것은 위험하고 그것을 어떻게 다루는가가 핵심"이라는 메시지를 가장 극적으로 보여주는 실험이기도 하다. 두 갈래는 상호 배타적이지 않아, "전역 밀도로 대략의 예산을 정하고 인스턴스 레벨 병합/제거로 세부 구성을 정제"하는 하이브리드 결합이 자연스러운 다음 단계로 보인다 — 실제로 DQA-DETR이 이미 이 결합의 초기 형태를 보여준다.

- **YOFOR — coarse-to-fine 서브영역 국소화라는 별도 축**: [[YOFOR]]은 위 dynamic query DETR 계열과 "밀집 영역에 자원을 더 쓴다"는 상위 목표는 공유하지만, DETR query가 아니라 이미지/픽셀 공간에서 직접 클러스터링으로 서브영역을 크롭한다는 점에서 완전히 다른 층위의 해법이다. [[QueryDet]](feature pyramid 레벨 sparse query)·[[FFSSTDNet]](patch 단위 CFD 필터링)과 함께 "어디를 볼지 좁힌다"는 세 번째 그룹을 형성하며, 여기에 배경 억제(FEM)와 long-tailed 클래스 완화(CBM)까지 한 파이프라인에 묶은 것이 특징이다. Long-tailed 문제를 다룬 것은 이 위키에서 YOFOR가 유일하다.
